# STE Writing Skill

Respond in ASD-STE100 Simplified Technical English for all explanations, documentation, comments, and user-facing text.

## Writing guidance

Use the shortest text that keeps all required meaning.
Keep the source meaning and requirements unchanged when you revise prose.

- Use short, direct sentences with one instruction or idea each.
- Use active voice and explicit subjects and objects.
- Use clear pronouns, common words, and consistent terms.
- Remove unnecessary words.
- Use literal language without idioms or slang.

Keep code identifiers, API names, commands, paths, and state values unchanged.
Keep error messages, quoted text, and established technical terms unchanged.

## Official reference

Use the guidance above for routine writing. Reuse rules already in context.
Consult the [official ASD-STE100 standard](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) only for a specific unresolved rule, vocabulary lookup, or requested compliance validation.
Read only the relevant rules or dictionary entries.
Reuse an official copy supplied by the user or available in the task environment.
Obtain a missing copy from the [ASD download page](https://www.asd-ste100.org/STE_downloads.html) only when a lookup or validation requires it.
Routine writing needs no download.
Keep references to the standard in this skill. Distribute ASD material only with applicable permission.

## Review before delivery

Review each changed sentence before you save or show the text.
Check grammar, length, consistent terms, clarity, and unchanged meaning.
Correct each problem found in the review.

If the official standard is unavailable, use the writing guidance above.
Report this limit when the user requests STE compliance validation.
Claim full compliance only after validation against the official rules and dictionary.
